# 交给 AI 的修改指令

把下面一段复制给能读写项目文件的 AI，并补充你的资料：

> 请把 Paper Tabs 换成我的个人主页。先读取 `content.js`、`theme.css` 和 `docs/design.md`。保留首页的纸张拼贴风格、个人介绍 → 文件夹项目 → 联系方式结构，以及文件夹点击和滚动交互。
>
> 我的姓名：[填写]；身份：[填写]；介绍：[填写]；关于：[填写]；邮箱：[填写或留空]；社交链接：[填写或留空]。我的 1–8 个项目：[逐个提供标题、描述、职责标签、封面路径和真实链接]。
>
> 用这些资料更新 `content.js`，并同步 `index.html` 的标题、描述和语言。缺失的可选信息留空，不编造客户、经历、指标或链接。图片来自我提供的素材；有封面时填写准确的 `coverAlt`。删除虚构示例人物和经历。配色与字体只通过 `theme.css` 调整；超过内容替换的改动请先说明影响。
>
> 完成后运行 `node scripts/check.mjs`（若有 Node），检查所有本地路径，并在桌面和手机浏览器确认无横向溢出、文字完整可读、链接可用、文件夹标签和减少动态效果正常。告诉我改了哪些文件，以及还缺哪些资料。只有我明确要求发布时才部署到我的新站点。

## 给执行修改的 AI

1. 先定位资料与配置字段，按真实内容更新。`content.js` 是内容的唯一来源，`index.html` 的静态元数据需同步；两者用于不同读取环境。
2. 文本通过 DOM 的 `textContent` 渲染；保留 URL 协议检查。新增字段同时更新本文或 README 的使用说明。
3. 内容变长时保留 `ResizeObserver` 驱动的适配和自然排列退路。不要以裁切描述或固定卡片高度换取整齐。
4. 有素材缺失时列出准确路径；隐藏可选资源或等待素材，不生成指向不存在文件的入口。
5. 完成标准：资料真实、1–8 项目可用、可选字段为空可用、长中英文文本无溢出、图片与链接可达、键盘操作与减少动态效果可用。若未运行浏览器检查，明确说明。

大幅改变信息结构、动画或布局属于二次开发，原模板的维护承诺不覆盖这些改造。
